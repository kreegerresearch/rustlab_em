This file guides AI coding tools working in this repository.

## Project Purpose

`rustlab_em` is a self-contained learning project exploring classical electromagnetics and Maxwell's equations through simulation. Each lesson is a single executable Markdown notebook pairing theory with runnable rustlab code that produces visualizations. The goal is to build physical intuition by seeing the math come alive as field lines, potential maps, propagating waves, and scattering patterns on real geometries.

This repo is **independent from rustlab** — never modify `../rustlab` from here. Instead, note needed features in `dev/rustlab/requests/` as standalone markdown proposals.

## Tool: Rustlab

Rustlab is a scientific computing CLI (`../rustlab`) with a scripting language optimized for matrix and signal processing work. Run scripts with:

```bash
rustlab run lessons/01-vector-calculus-and-fields/gradient_field.r
```

Run `rustlab` (no args) for an interactive REPL.

**Language and function reference:** `../rustlab/docs/quickref.md`
**Full function signatures:** `../rustlab/docs/functions.md`
**Notebook reference:** `../rustlab/docs/notebooks.md` and `../rustlab/examples/notebooks/README.md`

Before assuming any function is missing or writing a workaround, check `../rustlab/docs/functions.md` first. If truly missing, add a feature request file to `dev/rustlab/requests/` and implement a local workaround in the script.

## Directory Structure — source/site split

```
notebooks/                          # editable sources (committed)
  <slug>.md                         # one notebook per lesson
  README.md                         # editor-facing notes (skipped by the renderer)
lessons/                            # standalone .r scripts only
  <slug>/
    *.r                             # parallel to notebook code blocks
    *.svg|html|png                  # .r script artefacts — GITIGNORED
  README.md                         # explains the .r-script convention
site/                               # rendered (committed) — what GitHub displays
  README.md                         # hand-written index, preserved by the renderer
  <slug>.md                         # rendered notebook
  plots/<slug>/plot-N.svg           # captured figures
  index.html, <slug>.html           # interactive HTML build (`make html`) — GITIGNORED
docs/
  lesson-site-pattern.md            # reusable pattern doc for other rustlab courses
dev/
  plans.md                          # detailed lesson plans
  rustlab/requests/                 # feature request specs for upstream rustlab
README.md                           # top-level project overview
AGENTS.md                           # this file
Makefile                            # `make notebooks`, `make html`, `make lesson-NN`, `make notebooks-check`
```

Slugs are numbered two-digit with leading zeros (`<NN>-<topic>`). `notebooks/<slug>.md` is the only notebook file humans edit per lesson; the rendered output lives at `site/<slug>.md` and is regenerated by `make notebooks`. The `*.r` scripts are independent of the notebook pipeline; their plot artefacts (`*.svg`, `*.html`, `*.png`) land next to the script and are gitignored. Lesson dirs under `lessons/` are created on demand — a stub lesson with no scripts has no entry there. See [`lessons/README.md`](lessons/README.md) and [`notebooks/README.md`](notebooks/README.md) for in-tree notes, or [`docs/lesson-site-pattern.md`](docs/lesson-site-pattern.md) for the project-agnostic write-up.

## Lesson Notebook Format (`notebooks/<slug>.md`)

Use GitHub-flavored Markdown with LaTeX math: `$inline$` and `$$block$$`. Each ```rustlab``` block produces one figure and/or set of `print()` outputs; the renderer captures them automatically into `site/plots/<slug>/plot-N.svg` and ```text``` blocks in `site/<slug>.md`.

**Recommended structure:**

1. `# Lesson NN: Title` — H1, no suffix
2. Brief motivation paragraph
3. `## Learning Objectives` — 3–5 bullet points
4. `## Background` — prerequisite knowledge assumed
5. `## The Differential Operators` (or topic-specific formal definitions for reference) — pure-theory reference H2, can stay flat
6. One H2 per concept, each split into `### Theory` (prose + math, no code) and one or more `### Example — <descriptor>` (rustlab block plus a short setup paragraph). One H3 per logically distinct example — if a concept has both a quiver overlay and a magnitude heatmap, each gets its own `### Example — ...`. The H3 markers should always be present so readers can tell theory from examples at a glance; only genuinely all-reference sections (formal definitions, grid conventions) keep flat H2s
7. `## Standalone Scripts` — short table referencing the parallel `.r` files
8. `## Expected Numerical Outputs Summary` — Markdown table of every `print()` value students should see
9. `## Exercises` — 3–5 follow-up questions or script modifications
10. `## What's next` — one-paragraph forward link to the next lesson

**Template constraints:**

- **Do not** put `figure()` or `savefig()` in template code blocks; the renderer captures the active figure automatically.
- Variables persist across blocks within a notebook. Set up `[X, Y]`, `dx`, `dy` etc. once, reuse below.
- Use `clf;` at the start of each plot block to clear before drawing.
- Keep code blocks short — one concept each. Long blocks become unreadable in the rendered page.
- Comments inside code blocks: `%` (rustlab notebook idiom). Comments in standalone `.r` files: `#`.

**Style:** Derive equations step-by-step. Name every variable. State units explicitly (SI throughout). Connect math to physical intuition ("the divergence of $\vec{E}$ being zero in free space means field lines do not begin or end except on charges").

## Script Conventions (`.r` files)

The `.r` scripts are *parallel* to the notebook code blocks — same physics, runnable from a shell.

- **Header block** (required): script name, physical system, key equations, units
- Separate logical sections with blank lines and `# === Section ===` comments
- All plot output goes alongside the script: `savefig("foo.svg")` (no directory prefix). Artefacts are gitignored — the canonical rendered plots live in `site/`
- **Plot-then-save pattern**: `plot(v, "title"); savefig("file.svg")`. For heatmaps: `imagesc(M, "viridis"); title("..."); savefig("file.svg")`. The SVG is written next to the `.r` script and is gitignored
- Always `print()` the key numerical results a student should verify by hand
- Name files descriptively: `parallel_plate.r`, not `plot1.r`
- Keep scripts short enough to read in one sitting — split if over ~80 lines
- Units: SI everywhere ($\varepsilon_0 = 8.854\times10^{-12}$ F/m, $\mu_0 = 4\pi\times10^{-7}$ H/m, $c = 2.998\times10^8$ m/s). Note when scaled units are used for numerical conditioning.

## Running Lessons

Run from the `rustlab_em/` root:

```bash
make help              # list all targets
make notebooks         # regenerate every site/<slug>.md + plots from notebooks/<slug>.md
make notebooks-check   # CI-style guard: fail if site/ drifted from sources
make html              # build the interactive HTML view at site/index.html
make lesson-NN         # run the .r scripts for one lesson, e.g. make lesson-01
make all               # notebooks + html
make clean             # delete the interactive HTML build and .r script artefacts
```

After editing `notebooks/<slug>.md`, run `make notebooks` and commit both the source and all regenerated files under `site/`.

## Lesson Roadmap

The curriculum targets a "mini Ansys" endpoint: starting from vector calculus, students build up through static, quasi-static, frequency-domain, and time-domain PDE solvers, then put geometry and materials together to simulate real devices. Lesson 14 is a full end-to-end device capstone.

| # | Title | Focus | Status |
|---|-------|-------|--------|
| 01 | Vector Calculus & Fields | Grad, div, curl, Stokes', divergence theorem on grids | In progress |
| 02 | Electrostatics & Coulomb's Law | Point/dipole/ring fields, superposition, field lines | Planned |
| 03 | Gauss's Law & Electric Potential | Flux, $\nabla\cdot\vec{E}=\rho/\varepsilon_0$, equipotentials | Planned |
| 04 | Geometry & Material Maps | Rasterizing shapes into $\varepsilon(x,y)$, $\mu(x,y)$, $\sigma(x,y)$ arrays; region masks; boolean ops | Planned |
| 05 | Poisson & Laplace BVP — Dielectrics & Conductors | $\nabla\!\cdot\!(\varepsilon\nabla V) = -\rho$, FD relaxation, sparse solve, capacitor + dielectric-slab geometries | Planned |
| 06 | Magnetostatics & Vector Potential | Biot-Savart, Ampère, $\nabla^2\vec A = -\mu_0\vec J$ BVP with material $\mu_r$, solenoid, Helmholtz | Planned |
| 07 | Faraday's Law & Induction | Induced EMF, inductance, eddy currents | Planned |
| 08 | Maxwell's Equations | Displacement current, Poynting vector, energy flow | Planned |
| 09 | EM Wave Equation & Plane Waves | $c = 1/\sqrt{\mu_0\varepsilon_0}$, polarization, standing waves | Planned |
| 10 | FDFD — Frequency-Domain Maxwell Solver | Complex-valued sparse Helmholtz/Maxwell solve, layered transmission, scattering | Planned |
| 11 | FDTD — Time-Domain, Dispersive Materials, PML | Yee grid, leapfrog, TF/SF source, Drude/Debye/Lorentz via ADE, split-field PML | Planned |
| 12 | Waveguides, Cavity Eigenmodes & Radiation | Numerical generalized eigenvalue problem, rectangular modes, NF→FF transform, Hertzian + half-wave dipole | Planned |
| 13 | Transmission Lines, S-Parameters & Antennas | Coax/twin-wire $Z_0$, telegrapher + VSWR, multiport S-parameters via waveport excitation, 73 Ω radiation resistance | Planned |
| 14 | Capstone — End-to-End Device Simulation | Patch antenna + microstrip line: geometry → material map → FDTD → $S_{11}$ + gain pattern | Planned |

## Rustlab Feature Recommendations

See `dev/rustlab/requests/` for detailed per-feature specs. Running index:

- **Vector-calculus operators on grids** — `gradient()`, `divergence()`, `curl()` for 2D/3D uniform meshes (shipped). The backbone of every EM simulation.
- **Vector-field plotting** — `quiver()` and `streamplot()` (shipped); used in Lessons 01–03, 05, 06, 11.
- **Contour plotting** — `contour()` / `contourf()` (shipped).
- **Poisson/Laplace solver helpers** — stencil builders (`laplacian_2d(nx, ny, dx, dy)`, `laplacian_eps_2d(eps_map, dx, dy)`) returning sparse matrices ready for `spsolve` (Lessons 05, 06, 10, 12).
- **Helmholtz / FDFD stencil builder** — complex-valued Maxwell curl-curl operator on a Yee grid with PML (Lesson 10).
- **Generalized sparse eigensolver** — `eigs(A, B, n)` for cavity/waveguide mode problems (Lesson 12).
- **FDTD update helpers** — Yee-grid curl stencils, auxiliary-differential-equation (ADE) state helpers for dispersive media, split-field PML (Lesson 11).
- **Shape rasterization primitives** — `rect_mask`, `disk_mask`, `polygon_mask` over a grid (Lesson 04); boolean combine via logical array ops.
- **Animation export** — multi-frame SVG/GIF/HTML for time-domain visualization (Lessons 09, 11).

Before assuming any of these is missing, re-check `../rustlab/docs/quickref.md` and `../rustlab/docs/functions.md`.
